# Phase P6: Proactivity

Exit criterion (section 8): "Autonomy e2e + kill switch + injection suite."
Scope: FR-PRO-01..08, FR-UI-06, NFR-SEC-11.

## What was built
- **Proactive Bots (FR-PRO-01, FR-PRO-03):**
  - The per-Bot "Proactive" toggle is off on new Bots.
  - A Bot is autonomous when it is proactive, not paused, and its user has not paused all
    proactivity. This is checked again before every tool call (DL-062).
  - An autonomous Bot acts with no approval prompt, including outbound actions such as sending
    mail.
- **Routines and triggers (FR-PRO-02, FR-UI-06):**
  - Seven trigger types:
    - schedule (five-field cron, in the routine's time zone);
    - new mail (Gmail poll with a filter);
    - calendar event soon;
    - file watcher (Drive, or a folder in the Bot's computer);
    - webhook (a secret address, shown once);
    - MCP resource notification (both protocol eras);
    - daily digest at HH:MM, which gets the activity since the last digest.
  - Runs are queued, one at a time per Bot. Each run posts its trigger data, marked as outside
    content, in the Bot's chat and answers there (DL-064..DL-067).
  - The Routines tab shows:
    - each routine with its trigger, next run and last result;
    - run now, pause and resume, and delete;
    - the run history, with status and an "Open output" link to the message.
  - A routine can be created for any trigger. A webhook routine shows its address once.
  - Global search also finds routines (FR-UI-01).
- **Suggestions (FR-PRO-04):**
  - Autonomous Bots get a `suggest` tool that makes ranked cards in the tray.
  - "Do it" runs the task start to finish as an autonomous run. Cards can be dismissed.
- **Activity log (FR-PRO-05):** The log records each autonomous run's start and end, and every
  action in it with trigger, input summary, tool and result. Held, allowed and denied actions,
  suggestions and the pause switches are logged too. The log is shown in the global Activity feed
  and in the Bot profile (recent entries, plus "All activity" for that Bot).
- **Kill switch (FR-PRO-06):**
  - "Pause all" appears in the sidebar and the Routines tab, on desktop and Android.
  - Each proactive Bot has a "Paused" switch in its profile.
  - Pausing aborts running autonomous runs and drops queued ones (DL-063). Archiving a Bot stops
    its runs too.
- **Injection rule (FR-PRO-07, NFR-SEC-11):**
  - The runtime tracks how much outside content each reply holds (DL-060). A reply's level is
    raised by tool results, stored messages, delegations and marked memory or skills (DL-069).
  - For a Bot that is not autonomous, any call that changes something becomes an approval card
    once outside content is in play. The card shows the exact tool and input (DL-061).
  - Content seen in the Bot's own computer lets that work continue in the computer only. It
    cannot reach the host desktop, mail or any other tool.
  - Triggers and webhooks never start a Bot that is not proactive. They are recorded as
    `skipped` and never reach its model.
- **Push (FR-PRO-08):**
  - Run results, suggestions and held actions send the D-18 wake-up push (id only).
  - The per-Bot notification switch and the app-wide mute both apply.

## Review
A correctness and appsec review covered the runtime taint rule, the proactivity engine, the
routes (including the public webhook), the Google and MCP triggers, and the new screens.

Checked and found sound:
- every routine, run, suggestion and held action is looked up by its user;
- the webhook secret is compared as a hash, and a wrong secret or a deleted routine gives 404;
- trigger data and routine bodies are sealed at rest;
- the Bot-computer watcher passes its path as an environment variable, never in the script;
- UI text (titles, inputs, addresses) is rendered as text, never as HTML.

Fixed during the review:
- **Memory laundering:** a proactive Bot could save injected text to shared memory, and a Bot
  that is not proactive would later read it as clean content. Notes and skills written with
  outside content in play are now marked. Marked items stay out of prompts, and reading one
  taints the reader (DL-069). The learn pass marks too.
- **Host desktop:** content seen in the Bot's computer could continue on the host desktop,
  because both counted as one work surface. Each surface now stands alone.
- **Pause during a reply:** the rule used the Bot as it was when the reply started. It now
  reads the current state before every action.
- **Delegation in routines:** a proactive routine that delegated to a Bot that is not proactive
  failed outright. The delegate now follows its own rule, so its actions are held when outside
  content is in play.
- **Archived Bots:** archiving a Bot did not stop its runs. It now does.
- **Webhook secret:** the address with the secret was broadcast to all the user's devices on
  creation. It now goes only to the device that created the routine.
- **Watcher path:** a relative folder starting with "-" could be read as a `find` option. Such a
  folder now gets a `./` prefix.
- **Held action on an archived Bot:** the action was marked decided before the Bot was checked.
  The Bot is now checked first.
- **UI:** the Bot profile selected a new array from the store on every render, which looped. It
  now selects the list and then filters it.

Known limit: once a Bot that is not proactive has seen a web page in its own computer, it can
still act on that page with the computer tool, for example by filling in a form there. Blocking
that would end every computer task at its first screenshot. Nothing that page says can reach
the user's accounts, the host or any other tool (DL-060).
