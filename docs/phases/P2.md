# Phase P2: Bots & chat

Exit criterion (section 8): "Chat with a Bot on all clients using each model source."
Scope: FR-UI-01..04, 07..10, FR-BOT-01..05, model router (D-07), push (D-18), activity log base.

## What was built
- **Model router (D-07, FR-BOT-04):** six source kinds behind one provider interface:
  local OpenAI-compatible server (owner only), OpenAI API key, any OpenAI-compatible API
  (https only), Anthropic API key (official SDK), Claude subscription (Claude Code CLI with a
  `claude setup-token` token) and ChatGPT subscription (Codex CLI device login). Subscription
  CLIs run inside the Bot's Podman container with secrets passed by name only. Streaming,
  model listing, stop, and per-reply usage as reported by the provider.
- **Bots (FR-BOT-01, FR-BOT-02):** create, edit, archive (never destroyed); a primary Bot
  ("chief of staff") that cannot be deleted and can delegate tasks to other Bots through a
  `delegate` tool (depth 2, 8 tool turns) and summarize the result back.
- **Chats (FR-UI-02, FR-BOT-03):** direct chats and group chats; @mentions pick who answers;
  a Bot reply that mentions another Bot hands it the next turn (at most 3 hops). Threads one
  level deep, reactions, per-conversation drafts (sealed, survive restart), attachments
  (images to the model, text files inline, all sealed at rest), idempotent sends, stop,
  recovery of replies interrupted by a restart. All content is sealed with per-row AAD.
- **Search (FR-UI-01):** in-memory FTS5 index rebuilt from sealed rows at boot (no plaintext
  on disk); every word is quoted so query operators cannot be injected. Routines join in P4.
- **Library (FR-UI-04):** links, pages, images, videos and files a Bot produces, per Bot and
  global, grouped by day, pushed live to clients.
- **Usage (FR-BOT-05):** tokens and cost per Bot per source, only where the provider reports
  them (no estimates).
- **Activity log base:** sealed entries (kind + params), rendered client-side in either
  language.
- **Push (D-18):** wake-only payload `{t:'wake', id}`; endpoints accepted only on the
  owner-configured ntfy origin; optional ntfy sidecar; per-Bot notify setting and app-wide
  mute. Android: UnifiedPush connector registers with the ntfy app and shows a content-free
  notification. Desktop: native notification from the open connection.
- **UI:** chat-first home (sidebar on desktop, list + stack navigation on narrow screens),
  "+" menu, global search, chat view with streaming markdown/code (no raw HTML, no remote
  image loads), thread panel, composer with mentions, uploads and drafts, Bot profile from
  the chat header, Library and Activity views, Settings sections for models and keys, Bots,
  notifications and usage. Hebrew RTL with bidi-safe message bodies and previews.

## Review
Correctness and appsec review of the P2 server, UI and Android code. Checked: every route
scopes rows to the signed-in user (conversations, messages, attachments, drafts,
reactions, stop, Library, activity), a Bot can only use its owner's model sources, members
cannot add local or subscription sources, push endpoints cannot point anywhere but the
configured ntfy origin and redirects are refused, search queries cannot inject FTS
operators, markdown never renders raw HTML or loads remote images, and only http(s) and
mailto links open externally. Fixed during the phase: a stray separator after tool turns,
bidi punctuation in Hebrew previews, horizontal overflow on narrow screens, desktop links
with http or mailto doing nothing, and native plugin errors showing a generic message.
Commit `54fb93a` names FR-NOT-02, which does not exist; the requirement it covers is
FR-PRO-08 / D-18.
