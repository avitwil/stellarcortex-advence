# Phase P5: MCP and Google tools

Exit criterion (section 8): "MCP conformance; Google tools integration tests."
Scope: FR-MCP-01..05, FR-GGL-04..06.

## What was built
- **MCP client (FR-MCP-01/02):** Bots use MCP servers through the official TypeScript SDK 2.4.0
  (DL-055). Servers use either transport:
  - `stdio`: the command runs inside the Bot's computer, never on the host.
  - Streamable HTTP: both spec eras. `server/discover` is tried first (2026-07-28), with
    `initialize` and sessions as the fallback (2025-11-25).
  Supported features: tools, resources, prompts, the tasks extension, MRTR `input_required`, and
  form and URL elicitation. Tools appear to the model as `mcp_<server>_<tool>`, filtered by the
  per-server allowlist.
- **Input requests (FR-MCP-02/03):**
  - Forms a server asks for appear as a card in the app, filled with the schema defaults.
  - URL requests show the full address and open only after the user taps.
  - A form that asks for a secret (by field name, title or the password format) is declined, so
    secrets go through URL mode only.
- **Sign-in (FR-MCP-03):**
  - OAuth 2.1 with protected-resource discovery (RFC 9728), PKCE, `resource` (RFC 8707) and
    `iss` checks (RFC 9207).
  - Registration order: a pre-registered client, else the owner's Client ID Metadata Document,
    else dynamic registration (DL-057).
  - Tokens are sealed at rest and sent only in the Authorization header.
  - On the desktop, sign-in finishes through the loopback redirect; elsewhere the user pastes
    the address the browser lands on.
  - Sign-in loops stop after 3 attempts.
- **This server as an MCP server (FR-MCP-04):**
  - `/mcp` on the TLS port, for external clients such as Claude Code.
  - Clients can list and message Bots, list routines, and read the Library.
  - Owner access tokens only, stored hashed and shown once. Browser origins are refused (DL-058).
- **Management (FR-MCP-05):** Settings → MCP lets you:
  - add a server (http or Bot-computer stdio, with headers or env values that are never shown
    again), remove it, enable it, and turn it on per Bot;
  - check it, sign in and sign out;
  - list its tools, with an allowlist.
  The owner also sees the endpoint, the certificate, access tokens and the client metadata
  address. Members can add only public https servers, and every connection checks the address
  the name resolves to (DL-056).
- **Google (FR-GGL-04..06):**
  - One consent per user covers Gmail, Calendar, Drive and Contacts, with least-privilege
    scopes. The refresh token is sealed.
  - The Testing-mode 7-day limit is tracked. A day-6 notification and card offer a one-tap
    reconnect, and the connector shows "reconnect" once the limit has passed (DL-059).
  - Android uses Google's authorization client.
  - Bot tools: mail search, read, label, draft and send (header-injection safe); calendar read
    and create; Drive search, read and upload; contact lookup.
- **UI:** Settings → Google, Settings → MCP, and the cards above the chat (Google prompt after
  login, reminder, reconnect, MCP requests, the sign-in paste step), in English and Hebrew.

## Review
A correctness and appsec review covered the MCP hub, OAuth provider, input broker, the `/mcp`
endpoint, routes, Google connections and tools, and the new screens.

Checked and found sound:
- every server, input and token lookup is scoped to its user;
- owner routes use the owner guard;
- `/mcp` refuses any request that carries an Origin header;
- server responses never include env values, header values or client secrets;
- MIME headers strip CR/LF and Drive queries escape quotes;
- URL elicitation is https only, and the desktop opens only http, https and mailto links.

Fixed during the review:
- **Address check for members:** it looked only at the hostname text, so a name that resolves
  to a private address passed. Members' connections now resolve the name, refuse any
  non-public address and connect to the address they checked.
- **stdio for members:** members could add stdio servers. That is now owner-only.
- **Google reconnect:** re-consent revoked the old refresh token. Google's revocation ends the
  whole grant, so the new token died too. The old token is now replaced without a revoke, and
  the test mock models Google's grant-wide revocation.
- **Secret detection:** snake_case field names such as `password_confirm` and `pin_code` were
  missed. Names and titles are now matched by word.
- **Overlapping connections:** two connects at once could start two stdio processes or two
  sign-ins. They now share one connection.
