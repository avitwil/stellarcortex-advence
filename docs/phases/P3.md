# Phase P3: Bot computer and coding

Exit criterion (section 8): "Coding benchmark (FR-CODE-03) passes in a container on Linux,
Windows and macOS hosts."
Scope: FR-PC-01..09, FR-UI-05, FR-CODE-01..05, NFR-SEC-08.

## What was built
- **Bot computers (FR-PC-01, D-09):** one rootless Podman container per Bot from
  `images/bot-computer` (Ubuntu 26.04, Xfce, TigerVNC, noVNC, Chromium from Debian stable),
  created when the Bot is created, with a persistent home volume (FR-PC-03).
- **Isolation (NFR-SEC-08, FR-PC-04):** non-root user, no new privileges, every capability
  dropped except `CAP_SYS_CHROOT` (DL-054), default seccomp, only the Bot's volume mounted, no
  Podman socket, noVNC on the host loopback only, pasta networking without the host gateway,
  and the server refuses TCP connections that come from container network helpers (DL-031,
  DL-032). Chromium keeps its sandbox on.
- **Limits (FR-PC-05):** CPU, RAM and PIDs through cgroups, disk through a watchdog (DL-038),
  defaults editable in Settings → Computer.
- **Chat always works (FR-PC-06):** without Podman, or while the image builds, chat continues
  and the computer shows "preparing" with progress.
- **Setup (FR-PC-07):** `advence computer setup` installs Podman from official sources, sets
  up rootless use or the Podman machine, builds the image and turns on auto-start (DL-039).
- **GPU (FR-PC-08):** NVIDIA GPUs with CDI are passed through when present.
- **Host control (FR-PC-09, D-12):** per-Bot owner toggle, off by default; screenshot, mouse
  and keyboard on Linux (X11/Wayland), Windows and macOS with values passed in the environment.
- **Live view (FR-UI-05):** noVNC over the signed WebSocket (DL-033), take over and hand back
  with a server-side lock (DL-034), on desktop, browser and Android.
- **Coding engines (FR-CODE-01..05):** one engine interface with adapters for the Claude Agent
  SDK, Codex CLI and OpenCode, installed from official registries inside the container (C-06);
  credentials are Podman secrets passed by name at exec time; engine steps (diffs, commands,
  test output) stream into chat. A seeded benchmark repo is in `docs/bench/fr-code-03`.

## Review
Correctness and appsec review of the computer manager, Podman runtime, live-view proxy,
engines and host control. Checked: only a Bot's owner reaches its live view and take-over;
the take-over lock is enforced on the server; host control is refused unless the owner turned
it on; host command values are passed in the environment, never interpolated into a shell;
engine credentials never appear in argv, images or logs; containers cannot reach the server
API on loopback, the LAN address or the gateway. Fixed during the phase: Podman secrets are
created from the child environment (Node pipes are not FIFOs), exact "Running" matching in the
live view test, and Chromium's sandbox in rootless containers (DL-054).
