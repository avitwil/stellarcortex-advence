# Phase P4: Memory, learning and skills

Exit criterion (section 8): "Learn-pass and curator tests; third-party install pipeline."
Scope: FR-MEM-01..05, FR-LRN-01..06, FR-SKL-01..05.

## What was built
- **Vault (FR-MEM-01/02/04/05):** one git repo per user (DL-041) with `agents/<bot>/`
  (private to the Bot), `shared/` and `user/` (append-only, one writer per file), notes with
  YAML frontmatter and `[[wikilinks]]`, and a `MEMORY.md` index per Bot. Every write batch is a
  commit; rollback restores an earlier state as a new commit. Encrypted by default, with file
  names and commit messages sealed too (DL-042); the owner can switch to a plain vault for
  Obsidian after a warning, and back.
- **Retrieval (FR-MEM-03):** in-memory FTS5 index with title and tag weights (DL-043), index
  lines first and note bodies on demand through `memory_search` / `memory_read`.
- **Write guard (FR-LRN-02):** names, sizes, duplicates, a do-not-capture list and ownership,
  checked on every memory and skill write; each rejection is in the activity log (DL-044).
- **Skills (FR-LRN-03/04, FR-SKL-05):** Bots create and patch skills in Agent Skills format,
  view and run them (`skill_view`, `skill_run`), with view, use and patch counts and last use.
  Export gives a zip with the standard fields only.
- **Learn pass (FR-LRN-01):** after task replies, corrections, or every 10 user turns or tool
  iterations, a background review with memory and skill tools only, in the order the spec gives
  (DL-045).
- **Third-party skills (FR-SKL-01..04):** install from GitHub, skills.sh or a local folder
  (owner only). The source is pinned to its commit, the review shows the full SKILL.md, the file
  list, scan findings (scripts, network calls, prompt injection, secrets access) and spec
  errors, and nothing is active until the user approves (DL-047, DL-048). Update checks show
  the diff and wait for approval. Scripts run only inside the Bot's computer (DL-049).
- **Curator (FR-LRN-05/06):** weekly while idle, stale after 30 days and archived after 90
  (editable), pinned and locked skills untouched, JSONL ledger and snapshot per run, dry-run,
  run and rollback; consolidation off by default (DL-050, DL-051).
- **UI:** Settings → Skills (install and review, list with counts, pin and lock, update check,
  export, curator) and Settings → Memory (encryption, consolidation, curator days, history with
  restore), in English and Hebrew.

## Review
Correctness and appsec review of the vault, guard, skills, installer, curator and routes.
Checked: every route scopes skills, reviews and history to the signed-in user; Bots have no
install tool and cannot patch locked or installed skills; local-folder installs are the
server owner's only; archive paths, tar entries and skill names cannot leave their folder
(links and `..` are refused); download size, file count and file size are capped; markdown in
reviews is shown as text. Fixed during the review: commit messages leaked note names in
encrypted mode (now sealed), curator moves were not atomic (now one commit with copies), and
concurrent writes to one user's vault could interleave (now a per-user lock). Versions saved
while the vault was plain stay readable in git history; the warning says so (DL-042).
